# HammerDB TPC-C 数据库压力/稳定性测试技能 v2

一个用于对 SQL Server 数据库执行 TPC-C 基准测试与满负荷稳定性测试的 AI Agent 技能。支持 SQL Server 2008/2012/2014/2016/2019/2022。

[English Version](README_EN.md)

## 功能简介

本技能使 AI Agent 能够**直接执行**或**引导管理员完成**两类测试：

| 方向 | 目标 | 典型场景 |
|------|------|----------|
| **① 标准基准测试** | 测量峰值事务处理能力（NOPM/TPM），10–60 分钟出结果 | 性能摸底、配置对比、兼容性验证 |
| **② 稳定性压力测试** | 满负荷连续 6–48 小时，五判据正式验收（零错误/保持率≥90%/内存健康/零损坏/跑满时长）| "稳不稳"、"扛不扛得住 24 小时" |
| **③ 顺序自动化** | 先①后②一次完成全面评估 | 验收测试、上线前评估 |

## v2 版本更新（2026-08 实战驱动）

- **双方向决策树**：激活技能后第一步即与用户确认方向，含对管理员的明确引导话术
- **稳定性测试全流程（第 6 章）**：满载标定（吞吐平台判据）、迭代预算公式、无人值守预检、分钟级监控、五判据验收、退化诊断手册——经三服务器 6 小时实测验证（墙钟精确兑现 6h13m、捕获单台 5.6 倍吞吐退化并定位根因）
- **安全通道硬规则**：实测发现 WMI 远程执行、远程计划任务、xp_cmdshell（含关闭语句本身）均会触发主机安全系统强制断网；固化为"仅 SMB 文件读写 + 纯 T-SQL"两条通道及全套派生操作模式（本地任务 + SMB 改写控制、一次性任务再触发陷阱、自清理恢复脚本）
- **新增实战脚本**：`run_stability.tcl`（自动迭代预算）、`stability_monitor.ps1`（分钟级资源监控）、`check_status.ps1`（只读巡检）、`dbcc_check.ps1`（InfoMessage 捕获）、`restore_cleanup.tcl`（自清理恢复）
- **故障速查表扩容**：新增 10+ 条实测条目（监控 tpm 列陷阱、DBCC InfoMessage、PowerShell DataTable 拆包、2008 R2 建 VU 风暴、checkschema 误报、Timed 窗口起点等）

## 使用示例

- "帮我测一下这三台 SQL Server 的性能" → 标准基准测试
- "跑一个24小时满负荷稳定性测试" → 稳定性压力测试（自动标定→预算→监控→五判据验收）
- "全面评估，先基准再稳定性" → 顺序自动化

## 稳定性测试的四个静默陷阱（v2 核心价值）

1. **迭代上限在 Timed 模式下同样生效**——默认 1000 万次迭代会让"24小时测试"在 5–8 小时静默停止（实测案例：GUI 测试目标 24h 实跑 27%）
2. **思考时间会把负载压低 4 个数量级**——满载测试必须关闭 keyandthink
3. **内存占用 93–99% 是缓冲池正常稳态**——健康判据是硬页错误和 PLE，不是占用百分比
4. **Timed 计时窗口从 rampup 结束起算**——结束时间规划必须计入

安全方面：所有远程操作仅走 SMB 文件读写 + 纯 T-SQL 两条实测零告警通道，规避 WMI / 远程计划任务 / xp_cmdshell 三类会触发主机安全系统强制断网的操作模式。
